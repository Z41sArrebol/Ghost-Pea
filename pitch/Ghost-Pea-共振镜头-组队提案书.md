# Ghost-Pea「共振镜头」组队提案书

## 1. 产品方向

**简要概括**：一套由现场声音实时驱动的动态成像系统——让相机滤镜在拍摄过程中持续、低延迟地随声音变化，而不是拍完再后期。

**核心标语**：让镜头听见此刻。

**要解决的问题**：传统滤镜是静态预设，选定后整段视频一个风格；后期调色发生在拍摄结束之后。共振镜头把滤镜变成实时、连续、可感知环境声音的成像过程：

```text
Windows 系统音频 → 实时音频特征分析 → 滤镜参数编排与安全约束 → 实时相机画面处理 → 虚拟摄像头 / 实时录制
```

**关键边界**（同时也是差异化）：

- 不是音频可视化：不画波形、频谱、粒子，声音控制的是色彩、影调、Bloom、Halation、颗粒、局部对比度等**成像参数**。
- 不是后期处理：建立"声音 → 镜头变化 → 用户感知 → 用户反应"的实时闭环，低延迟本身就是产品价值（目标 <100ms）。
- 不替代物理滤镜：优势在于自动变化、参数连续可编程、可在直播中实时反馈。

## 2. 目标用户

| 用户 | 场景 | 核心价值 |
|---|---|---|
| 直播创作者（音乐/游戏/聊天主播、乐器演奏者） | 直播中背景音乐变化 | 镜头质感自动跟随，无需手动切滤镜，提升直播情绪表达 |
| 随手记录用户 | 听歌自拍、旅行短片、聚会、夜晚独处 | 拍摄时即见最终效果，记录的不只是画面还有当下的声音氛围 |
| 运动相机产品团队（主办方视角） | 骑行/滑雪/Vlog/演唱会 | 验证声音条件化成像能否下沉到相机 ISP/GPU 或伴侣 App |

产品语言统一使用"记录此刻氛围"，不声称判断用户真实心理情绪。

## 3. 核心功能

产品以 Audio-Aware Imaging Engine 为共享核心，提供两种模式。

### 3.1 Live Mode（直播模式）

- 选择系统音频来源和 USB 相机，选择动态滤镜主题。
- 实时预览处理后画面，输出到 OBS Virtual Camera 供直播/会议软件使用。
- 全局动态强度滑块，原始画面 / 处理画面一键 A/B 对比。
- 肤色保护、频闪保护、曝光保护。
- 状态面板：音频响应、FPS、延迟、设备连接状态。

### 3.2 Memory Mode（氛围记录模式）

- 一键录制 10–30 秒片段，动态效果直接写入成片。
- 可选保留原始画面。
- 生成氛围标签、主色和封面。

### 3.3 三个高完成度视觉主题（MVP 只做这三个）

- **Calm / Dream**：柔和对比、暖或青绿色倾向、高光扩散、轻颗粒暗角。
- **Bright / Alive**：明亮、肤色偏暖、中饱和、清晰高光。
- **Dark / Tension**：冷色深阴影、强对比、轻微色彩分离、胶片颗粒。

### 3.4 MVP 范围（P0 / P1 / P2）

- **P0（必做）**：UVC 相机预览、WASAPI 系统音频采集、快速音频特征（RMS/Bass/Mid/Treble/Onset/Centroid）、一个完整动态滤镜、参数平滑与静音回落、强度控制与 A/B、OBS Window Capture 输出。
- **P1（应做）**：三个主题、FPS/延迟/设备状态显示、OBS 录制与虚拟摄像头、参数录制与回放。
- **P2（有余力再做）**：AI 音乐情绪分类、人脸保护、人像分割、氛围封面。

**明确不做**：自研虚拟摄像头驱动、云端账号与社区、逐帧 VLM、生成式视频、移动端、大量滤镜模板。

## 4. 技术路径

### 4.1 总体架构

```text
Windows 系统音频
        ↓ WASAPI Loopback
Rust 音频采集
        ├─ 快速 DSP：RMS / Bass / Mid / Treble / Onset / Centroid
        │                       ↓ 30–60 Hz 参数事件
        └─ 16 kHz 单声道 PCM 滑动窗口
                                ↓ 0.5–2 Hz 二进制 Channel
                         前端 Web Worker（Essentia.js + TF.js，可选）
                                ↓ 氛围状态（Calm/Bright/Intense/Dark）
                         参数编排器（Attack/Release、防抖、回落）
                                ↓
UVC 相机 → getUserMedia → PixiJS Video Texture → WebGL2 Shader
                                ↓
                  Tauri 窗口 → OBS Window Capture → 录制 / 虚拟摄像头
```

### 4.2 技术栈

- **桌面容器**：Tauri 2 + Rust stable + TypeScript + Vite。
- **Rust 音频后端**：`wasapi`（系统音频回环）、`ringbuf`（有界环形缓冲）、`realfft`（频谱/频段能量）、`rubato`（重采样到 16 kHz 单声道）。
- **前端渲染**：`getUserMedia()` 取 UVC 相机，`requestVideoFrameCallback()` 跟随帧更新，PixiJS 管理 Video Texture 和滤镜链，WebGL2 自定义 Fragment Shader。
- **AI（可选增强）**：Essentia.js + TensorFlow.js 跑在 Web Worker，输出情绪概率；失败时基础动态滤镜照常工作。
- **输出**：OBS Window Capture，录制/直播/虚拟摄像头全部交给 OBS，不自研编码和驱动。

### 4.3 核心设计原则

- **视频帧不离开前端 GPU 链路**，不经过 Tauri IPC。
- **三层时间尺度分离**：快速 DSP（60–100 Hz）保证即时响应；中速趋势（2–10 Hz）控制动态幅度；慢速 AI（0.5–2 Hz）只决定氛围状态，不进低延迟关键链路。
- **AI 是增强项不是依赖项**：AI 超时/失败时快速链路照常工作。
- **参数编排器统一收口**：每个参数有最小/最大/默认值、Attack/Release、单位时间最大变化量、最短状态保持（2s）、切换交叉淡化（0.5–2s）、静音回落、频闪与曝光硬限制。

### 4.4 实时性预算

| 环节 | 目标延迟 |
|---|---|
| WASAPI Loopback | 5–15 ms |
| 快速特征分析 | 5–12 ms |
| Tauri 参数事件 | 0.2–2 ms |
| 等待渲染帧 | 平均 8.3 ms |
| PixiJS / WebGL2 | 2–8 ms |
| **本地预览合计** | **16–45 ms** |
| OBS 输出合计（含 Window Capture） | 31–80 ms |

验收目标：声音到画面 P50 < 80 ms，P95 < 120 ms；渲染稳定 60 FPS；连续运行 10 分钟无崩溃。
